## API 开发顺序与验收口径

1. **锁定 v0.4.1 契约**：使用 `docs/openapi.json`，首先对接 `/v1/capabilities`、`/v1/deployment-status`、`/v1/health`。新旧服务器版本应显式区分。
2. **核心业务**：目录与稳定分页 → 日线及历史覆盖 → 行业/概念排行 → 龙虎榜和席位 → 美国板块代理和 AI 观察池。分页沿用首屏 `snapshot_id`；409 时从首屏重读；401、422、501、503 分别处理，不把失败显示为“无数据”。
3. **数据状态**：返回交易日、源更新时间、采集状态和覆盖范围；区分配置池日线、全目录快照、历史初始化。当前 `/readyz` 可能因被用户暂停的 worker/备份陈旧返回 503，不能据此断言 API 进程已停。
4. **可选能力**：个股资金、新闻及经济事实需要各自实采验收。同花顺完整成员、合格逐日板块资金和完整计划事件源仍有缺口；客户端以 capabilities/501 展示不可用，不填造数据。
5. **上线准备**：确认根域名 A 记录指向目标服务器；备份生产库，部署同一验收版本、依赖和经过合并的生产配置；保留 worker 暂停状态。不要直接覆盖为默认全市场配置或盲跑历史升级脚本。
6. **公网验收**：检查 nginx 配置与证书后启用 HTTPS，验证鉴权、CORS、请求限流、证书续期，再用手机蜂窝网络和桌面网络分别验收。备案通过本身不等于 DNS、证书和网络已验收。

新版本日线 GET 在历史不足时会登记 `history_requests`，不直接抓取上游；worker 停止时队列不会执行。后续若需要恢复任何自动任务，应明确恢复范围，避免同时开启所有维护队列。
